This review tests the *scope* of the existing database owners; a changed source row, an announced rule and an emitted record are different kinds of evidence.

Run `python3 scripts/audit-9.0-source-inventory.py` to reproduce the old/new 448-path source inventory, then `python3 scripts/audit-9.0-final-source-routing.py` to reproduce [`final-source-routing.json`](final-source-routing.json). It classifies each path by its actual owner and reader or explicit schema boundary; the JSON contains the paths, row deltas (where supported), hashes and routes. ## Closure decision and residual risk

All **identified** #23 roster omissions are resolved and that issue is closed. The file inventory and release-article routing now have a reproducible path-by-path accounting and a more specific existing-owner map. However, this pass cannot independently prove the universal claim that *every* affected key across all retained source tables and all six articles has an exact implemented-output or demonstrated-irrelevance decision. In particular, (1) the six changed economy DB tables outside the standardized columns and their relationships to potential existing outputs, (2) source-only character traits/items and campaign scripts crossing existing skill/tech/unit boundaries, and (3) changed non-headline battle identities outside selected unit rows have classification by owner/scope but no exhaustive affected-key disposition. Source hashes, general owner validation and grouped section routing alone cannot discharge that stronger acceptance wording in #16.

**Keep #16 open** unless its acceptance criterion is deliberately narrowed or the remaining key-level decisions are documented and independently checked. Do not reinterpret this honest boundary as a request for a new mechanics schema, a hotfix migration, a full runtime simulation or resuming magic #14. Earlier pending-PR statuses in historical reports are checkpoints; the latest issue status controls merge state.
